# Foundry V2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Progression in Journey, driven by habits ticked on Today. The plan covers onboarding with goals, Christian Faith that can be switched off, Eye hours, the Gym statue, and Screen Time trends.

**Architecture:** Same app on branch `v2`. Domain logic lives in `src/domain/*`, with Vitest tests next to each module. A new `src/domain/progression.ts` holds the per-section progressions that Journey and milestones read.

**Spec:** `docs/superpowers/specs/2026-10-29-foundry-v2-1-design.md` (amends the V2 spec)

## Global Constraints
- Eye stages (hours): `[0, 1, 10, 25, 50, 100, 200, 365]`. Names stay as in V2.
- Faith and Ascent stages (days): `[1, 7, 14, 30, 60, 100, 365]`.
- Statue stages (points): `[0, 1, 12, 30, 60, 100, 160, 250]`. Points = sessions + PB milestones.
- There is one linked habit per section: `link: 'transmutation' | 'stillness' | 'faith' | 'gym'`.
- `settings.faith: boolean` and `settings.goals: string[]`.

## Review Focus
1. A user with no linked habits must get empty or zero progressions, never crashes (test `progression with no linked habits`).
2. Faith off must hide the Faith route, the Journey row, the onboarding suggestions, the flow verse step and the faith milestones (tests in progression and milestones).
3. A relapse logged today must zero the Ascent even if today is ticked (test `relapse today zeroes the ascent`).
4. A timed sit plus an auto-ticked meditation habit must not double count (test `sit and habit same day count once`).
5. Existing V2 preview state must be normalised: add `settings.faith`, `settings.goals` and the SR habit from `transmutation.start` (test `normalises v2 preview state`).

### Task 1: Types, migration and normalisation
**Files:** `src/types.ts`, `src/migrate.ts`, `src/migrate.test.ts`, `src/seed.ts`
- `Habit.link` widens to the four sections. `Habit.minutes?: number`.
- `Settings` adds `faith: boolean` (default true) and `goals: string[]` (default []).
- V1 → V2: "No PMO" stays as a habit with `link: 'transmutation'`. `transmutation` becomes `{ start: null, longestDays: bestStreak, relapses: [] }`, and the `needsPick` prompt happens on the Transmutation screen when no habit carries the link.
- `normaliseV2(s, now)`:
  - fills the missing settings
  - creates a "No PMO" habit with `link: 'transmutation'` when `transmutation.start` is set and no habit has that link, with ticks backfilled from the start day to today
  - gives a "Meditate" habit linked to Stillness `minutes: 30` if missing
  - `migrate()` calls it for version 2
- Seed: no starter habits. Onboarding creates them.
- Tests:
  - `v1 keeps No PMO as a transmutation habit`
  - `normalises v2 preview state`
  - `seed has no habits`
  - update the existing migration tests

### Task 2: Progression domain
**Files:** `src/domain/progression.ts` (+test). Also update `stillness.ts`, `faith.ts`, `transmutation.ts`, `completion.ts`, `milestones.ts`.
- `ascentDays(s, today)`: the SR habit's current streak, or 0 when a relapse falls on today.
- `relapseToday(s, now)`: unticks today and logs the relapse.
- `meditationMinutes(s)`: the sum over days of max(completed and partial sit minutes that day, the linked habit's minutes if ticked).
- `eyeStage(minutes)` uses the hour thresholds.
- `faithDays(s, today)`: consecutive days with the faith-linked habit ticked or prayer done.
- `faithStage(days)`
- `statuePoints(s)`, `statueStage(points)`
- `sectionProgress(s, today)` returns `{ section; title; value; stageName; stageIndex; pct; nextLabel }[]`, faith excluded when off.
- `dayItems` = scheduled habits only.
- Milestones use the new progressions and skip faith when it's off.
- Tests:
  - `progression with no linked habits`
  - `relapse today zeroes the ascent`
  - `sit and habit same day count once`
  - `eye awake at 365h`
  - `statue stage from points`
  - `faith days counts habit or prayer`
  - update the completion, stillness and milestone tests

### Task 3: Today = habits only; habit editor links + minutes
- Remove the section tiles. Keep the ring and the flow button.
- The editor's "Linked to" picker covers None / Transmutation / Stillness / Faith (only when faith is on) / Gym, plus a minutes stepper for Stillness and Faith.
- Workout finish, sit finish and Reader "mark as read" tick the matching linked habit.
- Check visually.

### Task 4: Journey progression + Screen Time trends
- **Journey:**
  - Progress (consistency) at the top.
  - One row per section: symbol, value and streak, a stage bar with "next: X". Sections are Transmutation, Stillness, Faith (when on), Gym (statue), Work, Screen Time.
  - Screen Time shows three brains: today, 7 days, 30 days.
- Add `avgMinutes(st, today, days)` to screentime (+ test).
- Screen Time screen shows the same three brains.
- Transmutation screen reads `ascentDays`. "I relapsed" calls `relapseToday`, and when no habit carries the link it offers to create one.
- Check visually.

### Task 5: Statue symbol + prompts
- `src/symbols/Statue.tsx` shows `/routine-app/statue/stage-N.png` when present, otherwise an SVG placeholder: a stone block with a figure emerging and more chisel facets per stage.
- `docs/statue-prompts.md` holds 8 image prompts, one per stage, from rough block to masterpiece.
- Gym screen gets a statue header.

### Task 6: Onboarding: goals → faith → suggestions
- Goals are multi-select. The faith step is "Christian, yes / Not for me".
- Suggestions are grouped by goal, none pre-selected, each with Why?. There's a custom-habit add, and Continue works with zero picked.
- Suggestions carry links and minutes: "Meditate 30 min" links to stillness, "No PMO" to transmutation, "Gym" to gym, "Read the Bible 20 min" to faith.
- You gets a Faith on/off toggle. When it's off, the Faith route, Journey row and flow verse step are hidden.

### Task 7: Verify, review, fix
- Run `npx vitest run && npx tsc -b && npx vite build`. Do a migration walkthrough (synthetic V1) and a fresh onboarding walkthrough in Playwright.
- Get a fresh whole-branch review of the V2.1 commits, then do one fix pass.
